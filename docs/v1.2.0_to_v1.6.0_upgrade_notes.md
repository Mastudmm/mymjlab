# mjlab v1.2.0 → v1.6.0 升级说明

> 对比基线：本项目 `AMP_vision` 分支（基于 v1.2.0）→ 官方最新 v1.6.0（2026-08-08）
> 涵盖子版本：v1.3.0 / v1.4.0 / v1.5.0 / v1.5.1 / v1.5.2 / v1.5.3 / v1.6.0
> 数据来源：`docs/source/changelog.rst`

---

## 0. 版本依赖升级总览

| 依赖 | v1.2.0 | v1.6.0 | 说明 |
|---|---|---|---|
| `mujoco` / `mujoco-warp` | 3.5 | **3.11** | 跨多个大版本，行为/类型桩已重新生成 |
| `rsl-rl-lib` | 5.0.1 | **5.4.2** | 带 `torch.compile`、std clamping；旧 checkpoint 可能不兼容 |
| `warp-lang` | ≥1.12 | 新版 API | 旧 `wp.context.runtime` / `wp.context.Device` 已移除 |
| `mujoco multiccd` | 可选 flag | **默认开启，flag 已移除** | `MujocoCfg.enableflags` 中若列了 `"multiccd"` 需删除 |
| `SimulationCfg.ls_parallel` | 可用 | **废弃并忽略** | 设置会发 `DeprecationWarning`，需移除 |

> ⚠️ **checkpoint 兼容性**：Go1 velocity 任务在 v1.5.3 启用了 `obs_normalization`，旧 checkpoint（无 normalizer buffer）无法加载，需重训。

## 1. 破坏性 API 变更（升级必改）

### 1.1 v1.6.0 破坏性变更

- **`CollisionCfg` 必须显式指定碰撞参数**：`contype`、`conaffinity`、`condim`、`priority` 不再静默用 MuJoCo 默认值；dict 形式的值必须覆盖所有匹配 geom（需加 catch-all `".*"` 条目）。
- **`CommandTerm._update_command` 签名变更**：新增 `env_ids` 参数（常规 per-step 更新时为 `None`，`reset()` 调用时为 reset 的 env_ids）。**自定义 command term 必须加该参数**，否则构造时抛 `TypeError`；并将 per-step 状态推进（如 motion frame index）限定到 `env_ids`。
- **`ViewerConfig` 改为 keyword-only**：位置参数构造不再有效。

### 1.2 v1.3.0 破坏性变更（影响面最大）

- **执行器延迟配置方式改变**：`DelayedActuatorCfg` 包装器、`DelayedActuator`、`DelayedActuatorGroup`、`delay_target` 全部移除。改为在任意 `ActuatorCfg` 子类上**内联配置** `delay_min_lag` / `delay_max_lag`。多目标延迟（`delay_target=("position","velocity")`）不再支持。
- **XML 执行器配置类合并**：`XmlPositionActuatorCfg`、`XmlVelocityActuatorCfg`、`XmlMotorActuatorCfg`、`XmlMuscleActuatorCfg` → 统一为 `XmlActuatorCfg`（自动从 XML 检测类型，可用 `command_field=...` 覆盖）。
- **`ActuatorCfg.armature` / `frictionloss` 默认值**：从 `0.0` → `None`（保留 XML 值，不再静默覆盖为零）。需旧行为则显式传 `0.0`。
- **`EntityData.generalized_force` 移除**（有 bug）：改用 `qfrc_actuator`（关节空间）或 `qfrc_external`（外力恢复）。
- **`TerrainImporter` / `TerrainImporterCfg` 别名移除**：必须用 `TerrainEntity` / `TerrainEntityCfg`。
- **`Entity.clear_state()` 废弃**：改用 `Entity.reset()`（旧方法不重置延迟缓冲，瞬移后指令会陈旧）。

### 1.3 v1.4.0 破坏性变更

- **相机分割输出格式变更**：`CameraSensorData.segmentation` 现存储 `(object_id, object_type)` 对，shape `[B, H, W, 2]`（旧为 geom-id-only 布局）。
- **`mujoco` 升到 3.8**：`multiccd` enable flag 移除（见上方总览）。

## 2. 地形（Terrain）相关修改 ⭐（重点）

> 你的 `AMP_vision` 正在改 `src/mjlab/terrains/config.py`，以下变更最相关。

### 2.1 课程地形模式行为变更（v1.3.0 #811，v1.5.0 #1027 修正）

- **每种地形类型恰好一列**：课程模式下 `num_cols` 被强制设为 `len(sub_terrains)`。
- **`proportion` 语义改变**：从控制"列数"变为控制"机器人在各列间的出生分布"。随机模式不受影响。
- **v1.5.0 修正**：课程模式地形难度在行间**确定性**，且能到达 `difficulty_range` 端点（之前不精确）。

### 2.2 地形预设系统（v1.3.0 新增）

- 新增 `STAIRS_TERRAINS_CFG` 预设（渐进式台阶课程训练）。
- 新增 `@terrain_preset` 装饰器，可从可复用预设组合地形配置。

### 2.3 具体地形配置变更

| 地形配置 | 变更 | 版本 |
|---|---|---|
| `HfRandomUniformTerrainCfg` | 新增 `scale_with_difficulty`，噪声幅度随难度递增（flat@0 → full@1） | v1.5.0 |
| `BoxSteppingStonesTerrainCfg` | 石块尺寸随难度递减；不再在平台周围留大间隙；网格难度无关，平台作为干净岛屿吸附 | v1.3.0 / v1.5.0 |
| `BoxNestedRingsTerrainCfg` | 改为等高同心脊，间隙随难度增大；按高度着色 | v1.5.0 |
| 金字塔楼梯类（`BoxPyramidStairs`/`BoxInvertedPyramidStairs`/`BoxOpenStairs`） | 修复 difficulty=0 时空几何边框，现生成与地面齐平的实体几何 | v1.5.0 |
| `HfPerlinNoiseTerrainCfg` | 修复 difficulty=0 编译失败 | v1.5.0 |
| `BoxRandomGridTerrainCfg` | 修复 difficulty=0 的 NaN 颜色与零除；修复中心平台 z-fighting | v1.5.0 |
| `BoxNarrowBeamsTerrainCfg` | 高难度下方形平台角落不再突出于梁之间，平台缩小 | v1.5.0 |
| `BoxRandomSpreadTerrainCfg` | 修复中心平台与地面重复 | v1.5.0 |

### 2.4 地形生成器与可视化

- **`TerrainGenerator` 不再覆盖自定义 geom 名**：仅未命名 geom 才自动命名 `terrain_{i}`（v1.5.1）。
- **高度场着色改为绝对高度**：发散调色板（地面下冷色、地面绿、地面上暖色），固定 scale，替代 per-patch 归一化。低幅度地形（如 `random_rough`）现为柔和着色而非高对比噪声（v1.5.0）。
- **地形 geom 质量设为 0**：避免静态地形体膨胀 `stat.meanmass` 导致粗糙地形上力箭头不可见（v1.3.0 #734/#537）。
- **`TerrainEntityCfg` 调试可视化默认关闭**：环境原点、地形原点、flat patches 站点默认 off，需 `debug_vis=True` 开启（减少 `nsite`、加速 `site_local_to_global` 内核）（v1.4.0 #942）。
- **地形生成不再打印 timing 信息到 stdout**（v1.5.0）。
- **`out_of_terrain_bounds` 终止条件修复**：改从 `terrain.terrain_origins` 读取有效网格形状并计入 `border_width`，避免机器人在有效地形上误重置或越界不重置（v1.4.0 #923）。

### 2.5 地形传感器

- **`TerrainHeightSensor`**（v1.2.0 已有）：`RayCastSensor` 子类，计算每帧地形上方垂直间隙。
- **`fit_terrain_normal` 加固**（v1.5.3 #912）：单 env 发散态产生的 NaN/Inf 协方差不再让 `torch.linalg.eigh` 崩溃整个 batch，回退到 up 向量。
- **射线传感器延迟修复**（v1.5.3 #998）：`sense()` 在缓存被预读 reward 重填后才重绑 hit 张量，导致观测/调试可视化滞后一步；现于 `postprocess_rays` 后失效缓存。

## 3. 执行器（Actuator）相关修改

### 3.1 新增执行器

- **`BuiltinDcMotorActuator`**（v1.5.0）：原生 MuJoCo `<dcmotor>` 封装，支持电压/位置/速度输入、反电动势、可选积分/摆率/电感/热/LuGre/齿槽扩展。
- **`BuiltinPdActuator`**（v1.4.0）：`IdealPdActuator` 的隐式积分版本，表达为原生 `<position>`+`<velocity>`，`implicit`/`implicitfast` 积分器会纳入 kp/kd 导数。**刚增益+大 timestep 下不发散**，`effort_limit` 通过 `jnt_actfrcrange` 做和-钳制。

### 3.2 延迟与配置

- **执行器延迟内联化**（v1.3.0，见破坏性变更）。
- **可融合执行器延迟统一**（v1.5.1 #1035）：ideal PD / DC motor 共享延迟配置时，每 env 用一个共享 lag（而非每组独立）；融合为单次 gather-delay-controllaw-write，移除 per-group host 开销。
- **`ActuatorCfg.viscous_damping`**（v1.3.0）：被动速度阻尼 `f=-b·v`，区别于 PD 的 `damping`。
- **`dr.pd_gains` / `dr.effort_limits`** 接受 `Operation | str`（v1.4.0 #971 修复）。

### 3.3 修复

- `create_velocity_actuator` 不再对连续关节（如轮子）设 `ctrllimited=True` + `inheritrange=1.0`（v1.3.0 #787）。
- 命令延迟现作用于执行器**全部** command target（position/velocity/effort），不再只作用 position（v1.4.0）。

## 4. 环境与训练（Env / Training）

- **`auto_reset` 标志**（v1.3.0 #900）：`False` 时 `step()` 跳过自动重置、返回终止观测，供需真实终止态的自定义训练循环。v1.6.0 进一步保证 `auto_reset` 与显式 `reset()` 留下**相同**的 command/event timer 状态（#1133）。
- **`RecorderManager`**（v1.3.0）：rollout 期间记录观测/动作/任意数据，提供 `record_pre_reset` / `record_post_reset` / `record_post_step` 钩子。
- **课程学习**：
  - `termination_curriculum`（v1.3.0）：与 `reward_curriculum` 共享调度引擎，含初始化校验。
  - `terrain_levels_vel` 修复（v1.5.3 #1094）：初始 reset 不再把所有 env 从 level 0 提到 level 1（忽略 `max_init_terrain_level=0`）。
- **`MetricsTermCfg.reduce` 扩展**：`"last"`（v1.3.0，取 episode 最后一步）、`"max"`（v1.5.0，episode 峰值）、`"sum"`（v1.6.0，episode 累计）。`per_substep` 标志（v1.3.0）每个物理子步评估。
- **manager 校验**（v1.4.0）：`RewardManager`/`TerminationManager`/`MetricsManager` 校验每个 term 返回 `(num_envs,)` 形状，违规则抛明确 `ValueError`。
- **`ObservationManager`**：跳过零活动 term 的观测组（v1.4.0）；修复 `NoiseModelCfg` 跨组共享 bug（v1.4.0，按 `(group_name, term_name)` 键）。
- **`reset(env_ids=...)` 部分重置修复**（v1.6.0）：不再给所有 env 追加观测历史/延迟缓冲帧；不再推进未重置 env 的有状态命令（避免 `MotionCommand` 倍速播放、自适应采样 EMA 折叠）（#1138）。
- **事件计时器**（v1.6.0）：区间事件 term 在 episode reset 时重新采样（之前跨 episode 携带倒计时，导致出生后立即 `push_robot`）。

## 11. 合并 v1.6.0 到 AMP_vision 的操作指南

### 推荐方案：新建分支 merge（不重写 AMP_vision 历史，最安全）

```bash
# 0. 确保 AMP_vision 干净且已备份（已有 origin/AMP_vision）
git checkout AMP_vision
git status                           # 确认无未提交改动

# 1. 新建升级分支（AMP_vision 本身不动）
git checkout -b AMP_vision_v1.6 AMP_vision

# 2. 合并 v1.6.0（用 merge，不用 rebase——146 个提交 rebase 风险极大）
git merge v1.6.0 --no-commit         # --no-commit 便于先审查冲突

# 3. 解决冲突（按上表策略），重点文件：
#    pyproject.toml / envs/mdp/* / managers/* / rl/* / scripts/* / sensor/* / tasks/velocity/*
git status                           # 查看冲突列表
#    用编辑器或 git mergetool 逐个解决

# 4. 适配破坏性变更（见第 10 节清单），尤其是 velocity_amp 内的执行器/命令/碰撞配置

# 5. 完成合并
git add .
git commit                           # 完成 merge commit

# 6. 验证
make format && make type             # 格式 + 类型检查
make test-fast                       # 快速测试
uv run python -c "import mjlab; print('import ok')"
# 跑一个 velocity_amp 小实验确认 AMP 训练正常

# 7. 验证通过后，可选：替换 AMP_vision 或发 PR
#    git push origin AMP_vision_v1.6
```

### 关键原则

- **用 merge 不用 rebase**：AMP_vision 已 push，rebase 会改写 146 个提交的历史，破坏协作。
- **冲突解决倾向 v1.6.0**：底层 API/修复类文件（managers、sensor、rl、scripts）以 v1.6.0 为准；业务逻辑类（velocity_amp 的 reward/curriculum 调参）保留你的实现。
- **velocity_amp 是纯新增**：不会与 v1.6.0 冲突，但需检查其依赖的底层 API 是否被破坏性变更影响（执行器、CommandTerm、CollisionCfg）。
- **先验证再合并回**：在 `AMP_vision_v1.6` 上充分测试后，再决定是否 fast-forward 或合并回 `AMP_vision`。
